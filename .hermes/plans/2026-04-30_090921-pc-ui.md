# Plan: PC 端适配为居中卡片式 UI，非全屏布局

## Goal
继续完善 flight-ludo 的响应式适配，重点调整 **PC 版 UI**：
- 不做全屏铺满
- 以“手机风格”的居中卡片/舞台尺寸显示在屏幕中
- 保持画面比例、留白和可读性
- 让 PC 端看起来像一个合适大小的游戏面板，而不是占满整屏的工作台

## Current context / assumptions
- 现有项目是 Vue 3 + TypeScript + PixiJS。
- 当前移动端与桌面端共用同一套页面结构，但桌面端更适合采用“中等尺寸、居中展示”的布局。
- 用户明确表示：**PC 版不需要全屏**，只需要一个合适大小的游戏 UI，视觉感觉类似手机端的游戏界面。
- 这意味着 PC 端的重点不是扩大 board，而是控制整体容器宽高、保持舞台在屏幕中央、并让外围留白更自然。
- 仍然要保留“玩法优先、简洁、图片驱动”的风格。

## Proposed approach
把 PC 端视为“桌面上的便携游戏卡片”而不是“铺满浏览器的页面”。

核心策略：
1. **限制主容器最大宽高**，让内容始终像一块独立游戏面板。
2. **保持内容居中**，上下左右都留出足够空间。
3. **复用移动端视觉密度**，不要在 PC 上把按钮、卡片、棋盘无限放大。
4. **只在必要时放大棋盘**，优先保证整体观感统一。

## Step-by-step plan
1. 检查当前 PC 端布局来源：
   - `src/App.vue`
   - `src/components/game/PrepareScreen.vue`
   - `src/components/game/PlayScreen.vue`
   - `src/components/game/ResultScreen.vue`
2. 明确 PC 端容器策略：
   - 页面本身保持全屏 viewport，但**内容区域不等于全屏**
   - 主内容限制在一个合适的最大宽度/高度区间内
   - 居中显示，四周保留背景露出
3. 调整 `App.vue` / 页面外壳：
   - 让背景图或背景层继续铺满视口
   - 但主内容容器不要继承“满屏铺开”的布局逻辑
   - 避免桌面端出现过大的空白操作区或拉伸感
4. 调整准备页（PrepareScreen）：
   - PC 端保持卡片式居中排布
   - 卡片宽度与间距更接近“手机 UI 放大一点点”的感觉
   - 不要为了桌面而扩展出过多横向空间
   - 保持两列或有限宽度的卡片区域即可
5. 调整游玩页（PlayScreen）：
   - PC 端不要做“全屏舞台 + 大面积空白”的模式
   - 让 toolbar、board、辅助区整体包裹在一个居中容器里
   - 设定 `max-width` / `max-height` / 纵向留白，让 board 维持合理尺寸
   - 如果当前 board 计算依赖屏幕尺寸，优先改成“受限容器尺寸”而不是直接吃满 viewport
6. 调整结果页（ResultScreen）：
   - 与准备页保持同样的桌面居中节奏
   - 按钮区不要被拉得太宽
   - 视觉上和手机端保持同一套密度
7. 如有必要，增加 PC 专属断点：
   - 在宽屏下限制主容器宽度
   - 在足够高的屏幕中限制主容器高度
   - 让 UI 看起来“规整、紧凑、像一个独立游戏面板”
8. 检查是否需要同步调整 board/canvas 计算：
   - 如果 board 在 PC 上过大，优先缩小外层容器
   - 如果 board 在 PC 上过小，再考虑微调 canvas 缩放或可视区域
   - 不要直接把整个页面内容做成真正的全屏布局
9. 验证不同桌面环境：
   - 普通笔记本屏幕
   - 1080p 桌面显示器
   - 宽屏显示器
   - 浏览器非最大化窗口

## Files likely to change
- `src/App.vue`
- `src/components/game/PrepareScreen.vue`
- `src/components/game/PlayScreen.vue`
- `src/components/game/ResultScreen.vue`
- possibly `src/composables/useFlightLudoPlayScene.ts`
- possibly `src/composables/flight-ludo-play-scene/boardRenderer.ts`

## Tests / validation
- `npm run build`
- `npm run lint`
- 如调整 board 相关计算，再补充：
  - `node --test src/composables/flight-ludo-play-scene/boardLayout.test.ts`
  - `node --loader ts-node/esm --test src/game/board-presets.test.ts`

Manual checks:
- PC 端内容不是全屏铺满，而是居中显示成一个合适大小的 UI
- 页面四周有自然留白，视觉像“桌面上的游戏卡片”
- board 和按钮没有被拉得过宽
- 手机端现有体验不被破坏
- 没有横向滚动条

## Risks / tradeoffs
- 如果 PC 容器限制过强，board 可能显得偏小。
- 如果 PC 容器放得太大，又会回到“全屏工作台”的感觉。
- 需要在“像手机 UI 一样紧凑”与“桌面上仍然清晰可操作”之间找平衡。
- 若同时改动移动端与 PC 端，容易把两个场景的节奏混在一起，需要分开验证。

## Open questions
- PC 端主容器希望更像“手机界面放大版”，还是更像“桌面游戏面板”？
- 桌面端是否需要单独限制 board 的最大像素尺寸？
- 结果页、准备页、游玩页是否都统一采用同一套桌面卡片宽度？
