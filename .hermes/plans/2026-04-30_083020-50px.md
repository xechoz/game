# Plan: keep finish slots 50px away from board center

## Goal
Fix the flight-ludo board layout so the finish/home lane endpoints no longer overlap at the exact board center. The last finish slot should stop short of the center and leave a 50px gap from the board center point.

## Current context / assumptions
- The board geometry is built in `src/composables/flight-ludo-play-scene/boardLayout.ts`.
- `buildFinishSlots()` currently interpolates each lane all the way to `slotCenterX/slotCenterY`, which places the final finish slot at the center.
- The user wants the endpoint to remain visually separated from the center by 50px.
- Existing tests only verify track length, so a new regression assertion is likely needed.

## Proposed approach
Adjust the finish-slot interpolation so the final slot lands on a point that is offset from the center by 50px along each lane’s direction of travel.

A likely implementation shape:
- Keep `slotCenterX` / `slotCenterY` as the conceptual center of the board.
- Introduce a `finishGap = 50` constant.
- Derive an adjusted target point for each lane anchor by moving the center point back by `finishGap` along the anchor-to-center vector.
- Interpolate each slot toward that adjusted target instead of directly toward the board center.

This preserves the overall lane shape while ensuring the terminal finish position does not collide with the center.

## Step-by-step plan
1. Inspect `buildFinishSlots()` in `src/composables/flight-ludo-play-scene/boardLayout.ts`.
2. Add a 50px terminal gap constant near the finish-slot logic.
3. Compute an offset target for each lane based on the lane anchor and the board center.
4. Replace the current `lerp(..., slotCenterX/Y, t)` destination with the offset target.
5. Verify the home-entry points still feed into the finish lanes as expected.
6. Add or extend a regression test in `src/composables/flight-ludo-play-scene/boardLayout.test.ts` to assert the final finish slot is 50px from the center, not at the center.
7. Run the relevant test file and the project build to confirm no layout regressions.

## Files likely to change
- `src/composables/flight-ludo-play-scene/boardLayout.ts`
- `src/composables/flight-ludo-play-scene/boardLayout.test.ts`

## Tests / validation
- `node --test src/composables/flight-ludo-play-scene/boardLayout.test.ts`
- `npm run build`

Validation checks to add:
- Final finish slot is not equal to the board center.
- Final finish slot sits 50px away from the center along the lane direction.
- Existing track length behavior remains unchanged.

## Risks / tradeoffs
- If the offset is applied incorrectly, lanes may become asymmetrical or too short.
- The “50px gap” may need to be interpreted as straight-line distance from center, not per-axis offset.
- If other UI layers already assume the finish slots reach the center, those assumptions may need updating.

## Open questions
- Should the 50px gap be exact Euclidean distance from the center, or a simple fixed axis offset?
- Should all four lanes stop at the same distance from center, even if that slightly changes their visual angle?
