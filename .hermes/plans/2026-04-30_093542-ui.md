# Plan: shrink the bases and tighten spacing for small phone screens

## Goal
Reduce the size of the player base areas in the flight-ludo board UI so they fit better on phone screens, and reduce the spacing inside each base so the pieces do not feel too spread out.

## Current context / assumptions
- The game board geometry is generated in `src/composables/flight-ludo-play-scene/boardLayout.ts`.
- The four player bases are created by `buildBaseSlots()` using `zoneSize`, `zonePadding`, `spread`, and `baseOutsideGap`.
- The current base layout is already working on desktop, but it is too large for small mobile screens.
- The user wants the bases visually smaller and the pieces inside them closer together, without changing core rules or the board path logic.
- The change should ideally preserve the existing board shape and only tune base sizing/spacing.

## Proposed approach
Make the base areas responsive-aware, with a smaller footprint on narrow screens.

Likely strategy:
1. Reduce the base square size and the outer offsets on mobile.
2. Reduce the internal piece spread so the four pieces sit closer together.
3. Keep the base positions anchored to the board corners so the overall board logic stays the same.
4. If needed, apply different base metrics for mobile and desktop while preserving the same slot structure.

## Step-by-step plan
1. Inspect `buildBaseSlots()` in `src/composables/flight-ludo-play-scene/boardLayout.ts`.
2. Identify the current base metrics:
   - `zoneSize`
   - `zonePadding`
   - `spread`
   - `baseOutsideGap`
3. Decide whether to:
   - shrink the current values globally, or
   - introduce mobile-specific tuning based on board size / viewport size.
4. Reduce the base footprint so the base boxes no longer extend so far outward on phone-sized screens.
5. Tighten the in-base piece arrangement by lowering the spread between the four piece slots.
6. Verify that the base still reads clearly as a 4-piece holding area and that the slots do not overlap the board edge.
7. Check the rendered result in the board renderer to confirm the new spacing does not break piece placement or the player-to-base mapping.
8. Update any regression tests if the board geometry expectations change.
9. Run build and targeted tests to confirm the layout remains stable.

## Files likely to change
- `src/composables/flight-ludo-play-scene/boardLayout.ts`
- `src/composables/flight-ludo-play-scene/boardRenderer.ts` if the visual base drawing needs to be tuned with the new size
- `src/composables/flight-ludo-play-scene/boardLayout.test.ts` if geometry assertions need updating
- `src/ui-layout.test.ts` if the layout regression test should also cover the smaller mobile base sizing

## Tests / validation
- `node --test src/composables/flight-ludo-play-scene/boardLayout.test.ts`
- `node --test src/ui-layout.test.ts`
- `npx eslint src/composables/flight-ludo-play-scene/boardLayout.ts src/composables/flight-ludo-play-scene/boardRenderer.ts src/ui-layout.test.ts`
- `npm run build`

Manual checks:
- On phone-sized screens, the bases are visibly smaller.
- Piece clusters inside the bases are tighter and easier to fit.
- The board still feels balanced on desktop.
- No base pieces spill into the outer board area.

## Risks / tradeoffs
- If the base is shrunk too much, the pieces may feel cramped or hard to distinguish.
- If only the spread is reduced but the base box stays large, the visual improvement may be limited.
- A single global change could make desktop bases feel too small, so per-breakpoint tuning may be safer.
- The board renderer may rely on current base extents for visual balance, so geometry changes should be checked visually.

## Open questions
- Should the base shrink only on narrow screens, or should we slightly reduce it everywhere?
- How small is acceptable before the base feels too cramped for four pieces?
- Do you want the base boxes themselves smaller, or mainly the pieces inside them packed tighter?
